# 磁盘小憩（Disk Nap）

[English](README.md)

磁盘小憩是一款实验性的 macOS 菜单栏应用，用于观察外置 SSD 功耗和测试自动休眠与唤醒。兼容 SSD 保持挂载并接受只读观察，菜单栏的自动休眠开关控制独立的 APFS 测试镜像。

## 快速开始

菜单栏应用需要 macOS 14 或更新版本和 Xcode 命令行工具。命令行工具和测试环境需要 Python 3.9 或更新版本。

Apple 芯片 Mac 可从 [GitHub Releases](https://github.com/grasscaograss/Disk-Nap/releases) 下载 ZIP，解压后将 `Disk Nap.app` 拖入「应用程序」。预览版采用临时签名，未经 Apple 公证。

也可以从源码编译：

```sh
git clone https://github.com/grasscaograss/Disk-Nap.git
cd Disk-Nap
make menubar
open "build/Disk Nap.app"
```

点击菜单栏的 SSD 图标。应用默认跟随 macOS 语言，可在底部「设置 → 语言」中选择简体中文或英文。运行 `open -n "build/Disk Nap.app" --args --preview` 可查看带标记的演示数据。

通过面板底部的「设置 → 登录时自动启动」，可让磁盘小憩在登录 macOS 后自动打开。

### 界面功能

- **概览**显示实盘无读写时长、实测休眠和功耗。点击功耗大数字可切换功率、采样耗电量和估算休眠节电量。合盖卡片记录 Mac 的电量变化和 SSD 休眠状态。
- **休眠策略**按当前阈值估算过去 7 天可休眠多久。开启自动休眠后，卡片显示实盘已确认的休眠时长和据此估算的节电量。点击电量可在 Wh 和占 Mac 满电容量的百分比之间切换。空闲记录足够且推荐值与当前设置不同时，才会显示阈值推荐。

应用在本机保留近 7 天的观察记录。功耗和电池占比取决于硬件和可用样本。目前已在 13 英寸 M4 MacBook Air 的一个 USB 端口验证功耗采集。耗电量只累加 Mac 清醒时有效采样之间的区间。合盖省电对照需要两种模式均有有效电池记录。

### 在测试镜像上试用自动休眠

先按[测试目录的自动唤醒实验](#测试目录的自动唤醒实验)创建 Python 环境，编译时传入该环境的 Python 路径。

```sh
make menubar LAB_PYTHON=/tmp/disk-nap-lab-venv/bin/python
open "build/Disk Nap.app" --args --show
```

应用启动时处于观察模式。开启「自动休眠」后，空闲超时或 Mac 进入睡眠会卸载测试镜像，通过「打开测试目录」访问文件会在原路径唤醒镜像。开启「仅用电池时休眠」后，接电时暂停策略，拔电后重新开始空闲计时。此过程中的物理 SSD 始终挂载，只用于观察。

## 命令行工具

在兼容的测试卷上检查设备和执行一次手动 USB 挂起。

```sh
make
./disk-nap probe "/Volumes/Your SSD"
./disk-nap cycle "/Volumes/Your SSD" --seconds 25 --verify-io
```

`probe` 只读检查已挂载的卷。`cycle` 安全弹出整个设备，待 USB 恢复后将原卷挂回。运行前请关闭盘上打开的文件。挂起期间可按 Ctrl-C 提前恢复。

`--verify-io` 会在 SSD 上创建临时目录，挂回后验证无缓存读取和同步写入，然后删除临时目录。如果恢复失败，请重新连接 SSD 并在「磁盘工具」中检查。

## 挂载时观察空闲时间

```sh
caffeinate -i ./disk-nap watch "/Volumes/Your SSD" --seconds 610
```

`watch` 接受兼容 SSD 上 APFS 或 exFAT 卷的实际挂载路径，也支持 `/Volumes` 之外的自定义路径。它无需 USB 控制组件。对于 APFS，它定位卷对应的物理盘，每 5 秒采集累计读写次数和字节数。计数变化、重置或采样中断超过两个采样周期时，空闲计时重新开始。可指定观察时长，或按 Ctrl-C 停止。

`state=idle-threshold` 表示物理读写计数在设定时间内保持不变，默认阈值为 600 秒。观察期间设备保持挂载。计数仅反映物理读写活动。

## 兼容环境

原型支持以 10 Gb/s 直连的致态灵·先锋版（ZHITAI SPIRIT PREMIUM）。挂起和恢复支持单个已挂载的 exFAT 卷，或由这一块物理盘单独承载的单个 APFS 卷。两种文件系统均在 1 TB 型号、ZTB50002 固件、Apple 芯片和 macOS 27.2 上验证过。

控制程序通过 `diskutil` 正常弹出磁盘，确认目标 USB 设备上的介质已全部卸载且关闭，再清除 USB 配置并通过 IOKit 请求挂起。恢复时还原原配置，必要时重新枚举设备。程序通过 USB 设备身份和卷 UUID 找回卷，即使 BSD 磁盘编号变化也能恢复。APFS 恢复还会验证同一卷已回到原挂载路径。

## 功耗实测

| 测试 | 挂载空闲均值 | USB U3 均值 | 低于 0.1 W 的非零 U3 样本 |
| --- | ---: | ---: | ---: |
| 25 秒命令行挂起 | 1.015 W | 0.085 W | 44 / 48 |
| 5 分钟参考实验 | 1.084 W | 0.078 W | 490 / 525 |
| 120 秒 APFS 命令行挂起 | 1.057 W | 0.085 W | 174 / 215 |

功耗由 Mac 的 USB 端口传感器独立采集。APFS 实验比较时排除了进入 U3 后的前 5 秒，其余读数为 0.057–0.142 W。原 APFS 卷回到自定义挂载路径，并通过临时文件读写验证。

## APFS 恢复

独立 APFS 测试镜像的 BSD 磁盘编号变化后，程序通过 UUID 找到卷，将其挂回原自定义路径，并验证无缓存读取和同步写入。另一项测试确认，只要某个进程的工作目录在卷内，即使该进程处于空闲状态，也可能阻止正常卸载。

## 测试目录的自动唤醒实验

实验通过 macOS WebDAV 提供固定路径，后端使用可丢弃的 APFS 磁盘镜像。后端 120 秒无访问或收到 macOS 睡眠通知时，程序会卸载镜像。文件访问会把镜像重新挂回私有挂载点。仅查询卷根目录属性时使用本地元数据。文件请求处理中会推迟卸载。

```sh
make
python3 -m venv /tmp/disk-nap-lab-venv
/tmp/disk-nap-lab-venv/bin/python -m pip install 'WsgiDAV==4.3.4' 'cheroot>=10,<12'
lab_dir=$(mktemp -d)
/tmp/disk-nap-lab-venv/bin/python -m disk_nap.lab "$lab_dir"
```

用输出中的 `files` 路径打开示例或创建临时文件。事件日志会记录镜像挂载、卸载和 macOS 电源通知。按 Ctrl-C 清理挂载。实验只在本机回环地址提供访问，只共享测试镜像，可验证路径保持和按访问唤醒。

要使用物理测试盘，请传入 `--usb-volume "/Volumes/Test SSD"`，路径须指向兼容的 APFS 卷。实验只共享新建的临时目录，根据物理读写计时，通过磁盘仲裁弹出整个盘，并保持 USB 挂起直到收到访问。访问或正常停止时，程序会检查卷 UUID 并恢复原挂载路径。请在内置盘上运行实验。生产用的文件代理还需要验证各应用的保存、文件锁和元数据操作。

实盘实验中，空闲阈值设为 120 秒，USB 在最后一次观测到读写约 126 秒后进入 U3，包含弹出时间。通过原路径发起的首次读取约 17 秒完成，包含 USB 恢复和 APFS 挂回。同步写入、重命名和读回也通过验证。

另一次实盘实验中，macOS 记录了 47 秒合盖睡眠。系统睡前、醒后且首次文件访问前，USB 端口均报告 U3。首次保存约 28 秒完成，包含一次重新挂载重试和重命名，并通过读回验证。
